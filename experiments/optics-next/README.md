# Two-vessel optical experiment

This is a research diagnostic, not the TSS renderer or a calibrated reproduction of the reference projector. The visible fields originate in two independently seeded Sailfish binary-fluid simulations. Each simulation has two density fields and a saved velocity field. Initial domains were seeded computationally. The simulations are periodic; fluid parameters, compression, illumination, and source geometry are not calibrated to a real projector. This experiment does not yet meet the requested photorealistic standard.

`output/diagnostic-paired-metal.png` is an actual 1280 × 720 Metal render on the Radeon Pro 5300M, and `output/diagnostic-paired-vulkan.png` is the corresponding NVIDIA Vulkan render with identical input, shader, and parameters. In this pair, 8 of 921,600 pixels differ by more than one 8-bit code value (maximum channel difference 31). An earlier shader produced a much larger difference; its cause has not been established. Both examples have visibly simplified contours and insufficient small-scale droplets.

A later 4K Metal attempt produced invalid all-zero-alpha readback for its first five frames; the resulting video is not a valid output. Subsequent 64 × 64 Metal dispatches also returned all-zero-alpha readback even though the shader writes opaque alpha for every pixel. The CLI now rejects any frame without opaque alpha and reports failure. macOS kernel logs during the investigation reported repeated IOAccelerator hardware-error and GPU-restart events. These reports do not establish the trigger or imply hardware damage. Further Mac GPU dispatches were stopped; see the cross-platform audit. Successful process exit from an older binary is not sufficient evidence of a valid frame. No production-quality 4K video or realtime performance has been established.

## Model and limitations

- `prepare_binary.py` converts actual `rho` and `phi` snapshots to separate 2-D signed-distance and component-density fields for each vessel, plus two dye-mass fields per vessel. Signed distances are reconstructed from thresholded density and optionally smoothed. They are not a 3-D solver result.
- `dye_transport.py` computes separately deposited dye masses using the saved velocity snapshots and a conservative finite-volume advection and diffusion model, with linear temporal interpolation between snapshots. The dye is an additional postprocessing simulation, not a field solved by Sailfish. Mass and positivity tests pass; phase confinement is approximate and can drift. Initial dye placements and diffusivity are modeled choices, not measurements.
- The GPU shader assumes a circular-arc meniscus through a thin cell with a 35° contact angle and reconstructs each vessel's interface from its 2-D field. It brackets crossings, computes Snell and Fresnel transmission, and integrates a model of dye absorption across phase segments. It assumes optical stacking, not separate projector beams. It samples five source angles and models defocus as displacement, not a calibrated lens. Incident absorption colors are converted from sRGB to a simple linear-light Beer attenuation approximation, not measured spectral absorption.
- The 24-step traversal can miss multiple crossings within a step; convergence and measured optical fidelity have not been established. Total internal reflection terminates a transmitted ray without tracing reflected paths. The volume implied by the reconstructed meniscus has not been checked against the fluid solver. The alpha guard detects unwritten pixels but does not prove valid color or correct physics.
- The example inputs are 255 × 253 grids with 11 frames separated by 50 simulation steps; output sampling is not an independently solved 4K liquid simulation. The H.264 encoder produces silent 8-bit video, not the requested high-bit-depth production master or music synchronization.

## Validation and reproducibility

The CPU checks are `python test_dye_transport.py`. GPU checks are `python test_optics.py <physical-optics-study-binary> <backend>` and exercise uniform transmission, Beer attenuation, equal-index interfaces and optical stacking. Those checks passed with an earlier shader; the revised shader has not passed them on the affected Mac since the readback failure. An unequal-index oblique-interface smoke test has been added but has not yet been run on the revised shader. Quantitative refraction and depth-convergence tests are still needed.

The successful paired stills were created with the tracer shader and input captured at `/private/tmp/tss-paired-tracer-optics/last.f32le` (SHA-256 `16a8c413b52380b7e342a5d3a49d80667092768e3ace73f6a6952c600730940a`), shader SHA-256 `bae3e44cd8b980fe30cdf71ab5c609f56ee86d1cc7ca1e7a8f0be3881addec58`, with arguments:

```

```

The prepared binary contains 5 groups per vessel: SDF, component 1 density, component 2 density, dye 1 mass and dye 2 mass, in little-endian f32; each group stores all vessels before the next group. Source snapshots were generated by the separate Sailfish experiment. The `/private/tmp` input is transient and is not included here; do not treat the command as standalone reproducibility until those inputs and their generation instructions are preserved.

The assumed circular cross-section is motivated by confined-fluid interface geometry, not a claim that the 2-D reconstruction solves the 3-D free surface: [Soligno et al., Journal of Chemical Physics (2014)](https://web.science.uu.nl/SCM/Articles/2014/Soligno_JChemPhys_2014.pdf).


## Bounded row dispatch

`TSS_TILE_ROWS` optionally limits the rows submitted per GPU compute dispatch. The value must be a multiple of 8 between 8 and 4096; for example, set it to `24` for the small NVIDIA comparison. Without it the study uses one dispatch per frame. Each tile is submitted and waited on separately. Setting `TSS_REPORT_TILE_TIMES=1` prints host elapsed time for each queue submit and wait; this is not a GPU timestamp or an isolated GPU execution measurement. A cleared output buffer and an opaque-alpha check detect missing writes, and validation and out-of-memory error scopes are checked after each tile. This does not guarantee a GPU workload is safe, catch every device fault, validate pixel colors, demonstrate a speedup, or constitute a real-time 4K capability. On Windows NVIDIA Vulkan, a 258 × 146 fixture rendered identically in RGBA with one dispatch and with 24-row batches, including a partial final batch; an invalid row size was rejected. This is a small-image equivalence check, not 4K stability or performance validation. No further Mac GPU dispatches were run following the reported hardware-error events.

## Per-step shared-transfer input

A later diagnostic uses one 160 × 160 vessel and steps 2–60 from a separately recorded NVIDIA Sailfish run. The six dye channels were advanced in a CPU replay using per-step phase transfer information; one independently initialized dye channel per fluid component is selected for this renderer, so four available channels are not shown. The replay's discrete per-step budgets and positivity were checked. This does not validate physical confinement or dye diffusion, and it does not correct the optical model's unresolved limitations.

The renderer input, transiently at `/private/tmp/tss-net-link-render-input/fields.f32le`, contains 59 frames of `[SDF, rho, phi, dye_rho, dye_phi]`, little-endian float32, with SHA-256 `9607f73b6739469c081c9b8a85990b3faddb2483abd250d4b0a61add45360972`. `prepare_binary.py` created it from `phase.0.` snapshots and the supplied dye fields using `--first-step 2`, the default reference density of 2.0, and one-cell interface smoothing. The upstream selected-dye NPZ has SHA-256 `80eebdc41c77f65eb0b443c67a0953f63351e3fda20348c4c3c8aceba48ae4a0`. The selected dyes are normalized by the same factor of 2.0 as the component densities. Source snapshots, dyes and input are transient and are not a permanent reproducibility bundle. The separately transported dye case described earlier remains a different, non-phase-consistent approximation; its limitations still apply to those earlier artifacts.

`TSS_DYE_STRENGTHS` optionally supplies exactly four comma-separated, independent optical-density multipliers in vessel/phase order: vessel 1 rho dye, vessel 1 phi dye, vessel 2 rho dye, vessel 2 phi dye. The default `1,1,1,1` preserves the prior study; zero disables that dye's modeled absorption. Each multiplier scales its RGB Beer absorption coefficient in linear light, and values must be finite and between 0 and 100. This represents a controlled model parameter, not measured concentration, an exposure adjustment, or calibration to a projector. The GPU fixture `test_material_strength.py` checks both pure phases at zero, unit and double optical depth; This fixture passed on the updated NVIDIA Vulkan binary for both pure-fluid phases. It does not validate boundary crossings, heterogeneous concentration, optical reconstruction, or correspondence with a real projector.

Each was evolved independently, with independently seeded dye fields, and the per-step replay budgets were checked.
