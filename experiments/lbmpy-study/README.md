# lbmpy / pystencils OpenCL candidate

This is source research, not an execution result. Neither the two-component nor Allen–Cahn model below has been tested on either TSS machine. No new Mac GPU workload should run until the recorded GPU recovery events are diagnosed.

## Candidate pair and license

- lbmpy `release/0.4.3`, commit [`358ebb116071fd46801eb7cf250416c264ae21b1`](https://github.com/lssfau/lbmpy/tree/358ebb116071fd46801eb7cf250416c264ae21b1).
- pystencils `release/0.4.3`, commit [`ddad5dafe6cb71c1a752a7a357536c4c8a0f55b8`](https://github.com/lssfau/pystencils/tree/ddad5dafe6cb71c1a752a7a357536c4c8a0f55b8). This satisfies lbmpy's declared `pystencils>=0.4.0,<=0.4.3` requirement.
- Both revisions declare AGPLv3. In addition, [lbmpy's license notice](https://github.com/lssfau/lbmpy/blob/358ebb116071fd46801eb7cf250416c264ae21b1/COPYING.txt) asserts that its generated kernels are also subject to AGPLv3. This needs review against TSS distribution and commercial plans; the notice is a statement by the project, not a legal determination.
- lbmpy declares Python >=3.8, SymPy >=1.5.1, <=1.9, NumPy >=1.11 and optional PyOpenCL. pystencils declares SymPy >=1.5.1, <=1.9, NumPy >=1.8, `appdirs`, `joblib`, and optional PyOpenCL. These declarations do not specify a complete tested lockfile. The notebooks import additional interactive/plotting packages. Both build configurations can compile optional native Cython/C extensions, so Windows compiler availability and installation paths need testing.

## Physics and backend evidence

The [two-component Shan–Chen notebook](https://github.com/lssfau/lbmpy/blob/358ebb116071fd46801eb7cf250416c264ae21b1/doc/notebooks/09_tutorial_shanchen_twocomponent.ipynb) uses separate distributions and densities for two coupled components, interaction forces, shared barycentric velocity, and periodic boundaries. It uses the data handler's target when generating its kernels. It runs on CPU by default and does not itself demonstrate OpenCL. A later version of the tutorial has one-step reference values, but those values must be checked against the exact equations and initialization of the chosen revision before treating them as an oracle.

The [Allen–Cahn notebook](https://github.com/lssfau/lbmpy/blob/358ebb116071fd46801eb7cf250416c264ae21b1/doc/notebooks/10_tutorial_conservative_allen_cahn_two_phase.ipynb) defines an immiscible two-phase model including surface tension and contact angle, but its automatic GPU selection checks for PyCUDA. Its boundary and synchronization paths therefore need separate OpenCL validation. The [authors' research paper](https://doi.org/10.1177/10943420211016525) describes the conservative Allen–Cahn method and OpenCL code generation. That paper does not establish that this particular revision runs this particular notebook on either TSS GPU.

The [pystencils backend](https://github.com/lssfau/pystencils/blob/ddad5dafe6cb71c1a752a7a357536c4c8a0f55b8/pystencils/kernelcreation.py) generates and JIT-compiles domain and indexed kernels for `Target.OPENCL`, and the corresponding [data handler](https://github.com/lssfau/pystencils/blob/ddad5dafe6cb71c1a752a7a357536c4c8a0f55b8/pystencils/datahandling/serial_datahandling.py) has a PyOpenCL array path. The same lbmpy revision has an [OpenCL-parameterized single-phase Poiseuille test](https://github.com/lssfau/lbmpy/blob/358ebb116071fd46801eb7cf250416c264ae21b1/lbmpy_tests/test_poisuille_channel.py); that test is not evidence that either multiphase example succeeds.

Pystencils [removed OpenCL](https://github.com/lssfau/pystencils/commit/9afc38bbc1c020525b36b7829aa1132938fc4af5) on 2021-11-22. Its `last/OpenCL` tag points to `0ed1a87b225ccfdf61cce5245a0b2207e20d8ccd`, two commits after release/0.4.3. It is an alternate investigation point, not the pair above. The current lbmpy README mentions an OpenCL extra while its current package metadata does not declare one; current support must not be inferred from that README.

## Proposed isolated Windows test

1. Coordinate with the active Windows rendering process. Prepare an isolated workspace and Python 3.9 environment, record the Python and compiler versions, and check out the two exact commits above. Resolve and record the entire dependency set; start with the requirements above and a Python-3.9-compatible PyOpenCL distribution. For example, PyOpenCL 2022.3.1 publishes a Windows x86-64 CPython 3.9 wheel, but compatibility with this old backend has not been demonstrated. Avoid changing the machine's global Python packages.
2. Use explicit PyOpenCL platform and NVIDIA-device selection, create its context and queue, and register both with `pystencils.opencl.init_globally_with_context`. First run the upstream single-phase OpenCL Poiseuille test and record versions, device, generated kernel build logs, pass/fail, and any skipped tests.
3. Run the unchanged two-component notebook on CPU as a baseline. Create a clearly identified experimental copy that sets its data handling target to `Target.OPENCL` and uses the explicit queue/context; preserve its equations, initial state, stepping, and precision. Record the precise adaptation and compare CPU and NVIDIA results at the same timesteps, including finite values, component minima, total component masses, and change in both fields. Do not assume bitwise equality. Reproduce the notebook's finite-value check; add an appropriate, separately documented short reference case and mass-drift tolerance before interpreting accuracy.
4. If successful, try the Allen–Cahn example separately, including its contact-angle and no-slip boundary kernels. Check mass conservation, static droplet shape/Laplace pressure, spurious currents, and grid/timestep sensitivity against documented test cases. Only then test transport of separate dyes, numerical stability under stirring/compression, performance, and reproducible integration with the renderer. Separate color transport and physical optical calibration are not established by either fluid notebook.

Exact dependency resolution, source compatibility, NVIDIA execution, GPU utilization, model validation, performance, packaging, and Mac execution remain open. The already-running Sailfish study remains the empirical baseline; this note does not select a replacement.
