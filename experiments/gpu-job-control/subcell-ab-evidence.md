# Sequential NVIDIA subcell comparison: run evidence

Two single-frame, 512 × 512 ray-export diagnostics ran sequentially on the Windows NVIDIA GeForce GTX 1650 Ti with Max-Q Design, Vulkan driver 617.14. Both ran through `gpu_job.py` using the same per-host reservation and 0.25-second requested NVIDIA telemetry interval; each returned zero and released its reservation after the job tree exited. No other GPU job was launched by this comparison. No claim is made about independent graphics activity outside the cooperative runner or device recovery from a GPU fault.

Both source inputs are the first frame under `../subcell-interface-study/output/frame-0000/`: `original.f32le` SHA-256 `46bf6cb54cf78dda715405aa6563e033237c8463e7b46c60cd9d57993addb1ab`, and `subcell.f32le` SHA-256 `1f86aa8ff1a57617b62bf1457685a726f93569a1976bead116d80365434f2ce4`. Input channels other than the reconstructed signed-distance fields were prepared by that separate study. The corresponding raw ray exports are `output/subcell-ab-validation-20261119/original-rays.f32le`, SHA-256 `b71bb2105131c6c015ac91394014976b554cbd3e1551b4b4b9a17826a7a847a1`, and `subcell-rays.f32le`, SHA-256 `018f21fd093c31daaf7bc817ee6eeca64a431489191342bd492fbeda77b2cb30`. Each contains 262,144 eight-float records. Independent CPU checks found all values finite and every final sentinel exactly 1. The original export hash also matches the earlier NVIDIA 512² export.

The frozen renderer was `%USERPROFILE%\work\tss-workspace\screen-rays-diagnostic\target\release\screen-rays.exe`; its source files matched the SHA-256 values in `../optics-next/windows-two-vessel-evidence.md` (`screen-rays.rs` `36539dc783142194dd348325376973cefc4a0756653e52c853ebd97ff933710c`; `screen-rays.wgsl` `e431ca429c3751750ec2e715d97d631e26fdb44e5e7cd50358e536f7fdede811`). The run helper is `run_subcell_comparison.py`, SHA-256 `9a7d21029fe0a539a705040e8678fbab3e6a308f03b598796dc526452fa458dd`; the runner was `gpu_job.py`, SHA-256 `97d4dcb08e24fe8eb953c7a8e04837a6d45b7977d46e17fee86b888e899e271a`. Both jobs set `TSS_TILE_ROWS=24`, `TSS_REPORT_TILE_TIMES=1`, `TSS_DYE_STRENGTHS=2,2,2,1` and used the same optical arguments as the existing 512² screen-ray run. The helper checks both input hashes before launching either job. Windows outputs are under `%USERPROFILE%\work\tss-workspace\gpu-job-control\subcell-ab-validation-20261119`.

The retained `original-runner.log` and `subcell-runner.log` record 22 host submit-to-poll timings each, respectively 0.432–0.815 ms and 0.552–1.064 ms. These are host timings, not GPU timestamps. The original CSV sampled 0–1% utilization, 0–6 MiB used memory, 44–47°C and 12.77–12.98 W; the subcell CSV sampled 0–1%, 0–6 MiB, 47–49°C and 12.96–13.33 W. CSV samples were far less frequent than individual dispatches, and `nvidia-smi` utilization and memory readings have their own sampling/reporting behavior; these observations do not capture or bound GPU peaks. Telemetry and runner logs are in `output/subcell-ab-validation-20261119/`. Their recorded clocks are UTC and depend on the host clock.

These experiments compare a geometric reconstruction using one stored fluid frame. They are not a validated physical liquid simulation, an image-quality approval, a video, an interactive performance test, or evidence of prevention of a GPU hang.
