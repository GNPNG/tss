# Splashsurf Windows study

This evaluates the upstream Rust surface-reconstruction CLI on the Windows test laptop, using
the upstream SPlisHSPlasH particle sample. Reconstruction runs on the CPU; no GPU
application or GPU dispatch is used in this study.

- Source: [InteractiveComputerGraphics/splashsurf](https://github.com/InteractiveComputerGraphics/splashsurf),
  commit `56d3e6ac444cf8540c238a4391483955a9484210`, MIT license.
- Input: [`data/double_dam_break_frame_26_4732_particles.vtk`](https://github.com/InteractiveComputerGraphics/splashsurf/blob/56d3e6ac444cf8540c238a4391483955a9484210/data/double_dam_break_frame_26_4732_particles.vtk),
  distributed by Splashsurf and identified in its header as SPlisHSPlasH data.
  The upstream benchmark uses this frame with particle radius `0.025` and a
  kernel compact-support radius of four times that radius.
- Build: Windows x86-64 MSVC, Rust/Cargo 1.98.1, checked-in Cargo.lock,
  `cargo build --release --locked --package splashsurf`. Cargo's documented
  `RUSTC` environment setting points to `rustup which rustc` for this process,
  because the system's `rustc.exe` symlink proxy failed with Windows error 448.
  No global settings were changed.
- The upstream [README](https://github.com/InteractiveComputerGraphics/splashsurf/blob/56d3e6ac444cf8540c238a4391483955a9484210/README.md)
  documents surface reconstruction from SPH particles and recommends `-r=0.025
  -l=2.0 -c=0.5 -t=0.6` with weighted smoothing and normals. The CLI maps
  smoothing length 2.0 to compact support radius 4.0 times the particle radius.

## Results

The release build completed successfully in 2 minutes 19 seconds; the upstream
checkout remained unchanged. The Windows executable's SHA-256 is
`5c514efbd30ddd2d9bb6d7297cf362de441abec6beb0358b6e2346e0a861c76e`.
The input fixture's SHA-256 is
`f09f117fbc585d6a1d9c8dfbcc9d4bf4152a76e1e336433e1732437ddc7b6a98`.

An initial PowerShell invocation passed unquoted short options in the form
`-r=0.025`; PowerShell changed the arguments and the CLI rejected them. No mesh
was generated by that attempt. The successful invocation used separate short
option values and quoted the `--option=value` arguments:

```powershell
Set-Location "$env:USERPROFILE\work\tss-workspace\splashsurf-windows-study"
.\source\target\release\splashsurf.exe reconstruct `
  .\source\data\double_dam_break_frame_26_4732_particles.vtk `
  -r 0.025 -l 2.0 -c 0.5 -t 0.6 `
  '--mesh-smoothing-weights=on' '--mesh-smoothing-iters=15' `
  '--normals=on' '--normals-smoothing-iters=10' '--check-mesh=on' `
  '--output-dir=output' '--output-file=frame26.obj'
```

The CLI read 4,732 particle positions and wrote an OBJ with 130,932 vertices
and 261,992 triangles after cleanup and smoothing. Its mesh checks reported no
holes, non-manifold edges or vertices, or inverted normals. The log reported
0.512 seconds for the whole operation including output, for this single small
fixture and this run; this is not a general performance benchmark.

The 20,661,391-byte generated `frame26.obj` is retained locally (ignored by
Git) and on the Windows test laptop in the study's output directory. Both copies have SHA-256
`264ba0cc3b67ee7f18070ba7f14dffa7d32f46d3dbf679199b776b5537670414`.
The run log is `reconstruct.log` in this directory.

This study does not establish a coupled multiphase solver, liquid optics, live
performance, GPU acceleration, or 4K rendering.
