# Splashsurf upstream surface reconstruction study

This study evaluates the native Rust CLI and library from <https://github.com/InteractiveComputerGraphics/splashsurf> at commit `56d3e6ac444cf8540c238a4391483955a9484210`, version 0.14.1, under the upstream MIT license retained as `LICENSE.Splashsurf`. It reconstructs surface meshes from SPH particle data; it does not solve the fluid simulation or establish oil-water interfacial physics. No GPU workload is involved in this CPU-only study.

The official upstream file `data/double_dam_break_frame_26_4732_particles.vtk` identifies its contents as SPlisHSPlasH particle data and has 4,732 points. The upstream benchmark `splashsurf_lib/benches/benches/bench_full.rs` uses this exact file with particle radius 0.025, compact support radius four times the particle radius, cube edge length 0.3 times the particle radius, and threshold 0.6. The README describes a CLI `--smoothing-length` of 2.0 as producing that support radius. This is an existing upstream sample, not output generated by this study's own SPlisHSPlasH build.

The active Rust toolchain is 1.87.0, but rustup also has 1.88.0 installed, meeting the `rust-version = "1.88"` declared by the pinned CLI. No Rust build or reconstruction result is claimed until recorded below.

The unmodified pinned CLI and library manifests each claim Rust 1.88, but `cargo build --locked --release -p splashsurf` failed with Rust 1.88.0 before compilation: the checked-in lockfile selects nalgebra 0.35.0, safe_arch 1.0.0, and wide 1.4.0, each declaring Rust 1.89 in its published Cargo manifest. `splashsurf_lib/Cargo.toml` directly requests nalgebra 0.35. The exact failure is preserved in `evidence/build-rust-1.88-failure.log`.

`patches/splashsurf-msrv-1.89.patch` proposes correcting the CLI and library minimum to 1.89 without changing dependency versions or bypassing Cargo's checks. The patch is in a separate checkout and has been verified for the CLI release build on this Intel Mac with Rust 1.89.0. A build using the already-installed Rust 1.100.0 stable toolchain, which matches the upstream CI's use of stable, is a separate test and cannot prove the proposed minimum.

The unmodified source and lockfile built successfully in release mode with Rust 1.100.0 stable using two build jobs in 9 minutes 55 seconds. The source's `release` profile enables LTO. Running the native CLI with the upstream benchmark's physical and reconstruction parameters produced a PLY surface from the upstream SPlisHSPlasH particle fixture:

```sh
RAYON_NUM_THREADS=2 ./build/release/splashsurf reconstruct \
  vendor/upstream/data/double_dam_break_frame_26_4732_particles.vtk \
  -r=0.025 -l=2.0 -c=0.3 -t=0.6 -o output/double-dam-surface.ply
```

With a 120-second process limit, the command succeeded in 2.47 seconds wall time. The binary little-endian PLY contains 465,582 vertices and 931,288 faces; its SHA-256 and the process output are recorded in `evidence/`. The 17 MB mesh itself is retained locally in the git-ignored `output/` directory. This checks the sample-to-mesh path, not oil-water dynamics, optical rendering, visual quality, or real-time performance. The upstream README warns that parallel reconstruction is not deterministic, so the checksum identifies this particular output, not an expected checksum for every run.

The separate patched checkout was checked with Rust 1.88.0 and Cargo rejected it with a direct Rust 1.89 requirement for both Splashsurf packages, as intended. The patched, locked CLI release build succeeded with Rust 1.89.0; the final invocation resumed a previously interrupted build and took 168.68 seconds, excluding earlier work. Its CLI reconstructed the same upstream particle fixture in 1.28 seconds, producing 465,582 vertices and 931,288 faces. This validates the corrected minimum only for this tested target and feature selection.

The exact Rust 1.89 build invocation used the separate corrected checkout and target directory:

```sh
CC=/usr/bin/clang CXX=/usr/bin/clang++ CARGO_TARGET_DIR="$PWD/build-1.89" \
  CARGO_BUILD_JOBS=2 rustup run 1.89.0 cargo build --locked --release \
  -p splashsurf --manifest-path vendor/msrv-corrected/Cargo.toml
```

The patch corrects the declared minimum to the minimum required by the tested lockfile; it does not make the dependencies compile with Rust 1.88. Rust 1.89.0 was installed via rustup for this verification. The original checkout is untouched; the patch, failure output, build output, and reconstruction timing are recorded in `patches/` and `evidence/`.
